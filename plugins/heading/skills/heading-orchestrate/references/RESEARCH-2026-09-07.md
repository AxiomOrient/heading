# OpenAI 공식 조사 — 2026-09-07

기준일: **2026-09-07, Asia/Seoul**. 요청한 최신 범위는 **9월 6일~7일**이다. 검색 결과의 “오늘 수집” 표시는 발행일이 아니다. 아래 문서는 이 작업에서 직접 확인했다. 모델 실행이나 사용자의 계정 접근 여부를 검증한 것은 아니다.

## 2026-09-08 정책 보충

사용자 운영 정책에 따라 Astra는 기본 low(Light), 위험한 판단 및 low 실패 후 medium, 매우 어려운 특수 작업에만 근거와 허용 예산을 기록한 ultra를 사용한다. high/xhigh/max는 Astra 라우팅에서 제외한다. 기존 API 지원값 설명은 API의 능력 목록이며 Heading의 허용 목록이 아니다.

9월 8일 다시 읽은 [Astra 발표](https://openai.com/index/gpt-6-astra/)는 표의 점수를 모든 effort 중 최고값이라고 설명한다. 이를 모든 작업에서 medium이 최고점이라는 증거로 해석하지 않는다. 이 정책은 사용자 선호이며 Heading 성능 최적성은 아직 미측정이다.

[Codex native subagent 문서](https://learn.chatgpt.com/docs/agent-configuration/subagents#choosing-models-and-reasoning)는 지원 모델에 한해 `ultra` reasoning effort를 설명한다. 같은 문서의 ChatGPT Work Ultra는 최대 추론과 자발적 위임을 포함하는 제품 모드다. [Astra API 명세](https://developers.openai.com/api/docs/models/gpt-6-astra)는 low/medium/high/xhigh/max를 열거하며 ultra를 포함하지 않는다. native 요청에는 실제 호스트 schema·모델 지원 확인이 필요하며 API max로 자동 치환하지 않는다. 아래 9월 7일 기록보다 이 보충 정책이 우선한다.

## 결론과 적용

Astra의 정확한 API 식별자는 `gpt-6-astra`, Luna는 `gpt-5.6-luna`다. Heading은 복잡하거나 불명확한 작업에 Astra low, 명확하고 검증 가능한 반복 작업에 Luna xhigh를 요청한다. Luna max는 제한된 재시도이며 위험한 판단을 작은 모델의 긴 추론으로 대신하지 않는다. 이 조합의 실측 최적성은 **[UNVERIFIED]**다. `model-policy.json`은 `CANDIDATE_NOT_BENCHMARKED`로 명시한다. [S1–S4]

## 정확한 모델·추론 해석

Astra는 복잡한 추론, 코딩, 컴퓨터 사용, 조사, 문서 작업을 대상으로 한다. API 문서는 low/medium/high/xhigh/max를 지원하며 none은 지원하지 않는다고 명시한다. 문맥 1,050,000과 최대 출력 128,000은 API 명세이지 모든 Codex 실행의 사용 가능 용량 보장이 아니다. 실제 호스트 설정을 강제로 이 값으로 덮어쓰지 않았다. [S2]

Luna 문서는 비용 민감·대량 작업을 대상으로 하며 none/low/medium/high/xhigh/max를 지원한다. API 지원은 해당 사용자의 앱·요금제·하위 에이전트 경로에서 사용 가능하다는 증거가 아니다. [S3]

Codex는 Astra를 가장 어려운 종단 작업에, Luna를 명확한 반복 작업에 구분한다. Light는 UI 표현이며 CLI의 low에 대응한다. Max와 병렬 위임을 포함하는 Ultra는 서로 다르다. Heading은 Ultra, pro mode, Fast mode를 추론 강도의 별칭으로 사용하지 않는다. [S4]

**[ASSUMPTION] 정책 선택:** Astra low는 복잡 작업의 시작 후보이며 성능 보장이 아니다. 공식 가이드는 다른 effort에서 이관할 때 기존 유효 effort를 보존하고 비교하라고 안내한다. 이번 변경은 기존 Sol medium과 동등 성능이라고 주장하는 단순 마이그레이션이 아니라 사용자 요청에 따른 새 후보 정책이다. Luna xhigh 역시 기본 비용 최적값이라는 근거는 없다. 둘 다 대표 작업으로 재평가해야 한다. [S5]

## 프롬프트에 반영한 변화

Astra 가이드는 질문 때문에 일찍 멈추는 경향, 파일 지침에 대한 민감성, 자세한 응답, 위임 정도, 작은 변경에서 과도한 테스트를 조정할 수 있다고 설명한다. Heading에는 이미 허용된 작업의 지속, 중요한 모호성만 질문, 사용자 요구와 스킬 기본값의 구분, 위험에 비례한 검사, 짧은 결과 요약을 반영했다. 상위 지침·실제 권한은 그대로 유지한다. [S5]

역할 파일이 model 또는 model_reasoning_effort를 고정하면 현재 Codex에서는 명시적 spawn 값보다 우선한다. 따라서 기존의 “역할 파일은 기본값일 뿐”이라는 지침은 최신 호스트 규약과 충돌했다. 네 역할에서 두 필드를 제거하고 dispatch에 둘을 함께 전달하게 했다. 역할 이름·sandbox·독립 리뷰·단일 작성자 계약은 보존했다. 같은 문서 일부 예시는 이전 모델 이름을 사용하므로 모델 식별자는 최신 모델 문서를 정본으로 삼았다. [S6]

프로필은 현재 Codex의 별도 `heading.config.toml` 파일 방식이 맞다. 오래된 `[profiles.heading]` 중첩 형식으로 바꾸지 않았다. 스킬의 `agents/openai.yaml`에는 모델 설정을 꾸며 넣지 않았다. 이 파일의 역할은 표시·호출 정책·도구 의존성이다. [S7,S10]

## API를 직접 붙일 때의 경계

이 패키지는 OpenAI API 클라이언트를 추가하지 않았다. 후속 구현 시 Astra 도구 호출은 Responses를 사용하고, 지원하지 않는 temperature/top_p/top_logprobs 및 관련 logprobs 설정을 제거한다. reasoning.effort 변경, 캐시 설정, async 도구 호출은 각각의 호환 조건을 확인해야 한다. 이 기능들을 Codex spawn 도구의 인자로 추측해 전달하지 않는다. [S5]

새 async 도구나 컨텍스트 관리가 제공된다는 사실은 자동 도입의 이유가 아니다. Heading은 한 명의 작성자와 명시적인 완료 관찰을 유지한다. 계정별·클라이언트별 capability는 실행에서 별도로 확인한다. [S4,S6]

## 9월 6일 자료의 실제 의미

An Alien Mind는 Astra 계열을 연구하면서 추론 과정 모니터링에만 의존하는 능력이 약해지는 문제를 논의한다. 여기서 Heading이 도출한 설계 판단은 **출력 설명보다 테스트·실행 로그·상태 read-back을 우선**하는 것이다. 논문의 주장을 특정 Heading 회귀 결함의 증거로 삼지는 않았다. [S8]

Research acceleration은 내부 연구 업무의 에이전트 사용과 작업 변화에 관한 관찰이다. 입력 난도, 성공 조건, 실행 환경이 Heading과 다르므로 그 결과로 “Astra low가 Luna max보다 몇 배 낫다”는 수치를 만들 수 없다. 선택 정책, 실행 성공, 승인된 결과를 나눠 측정하는 쪽으로 반영했다. [S9]

## 비용과 성능 판정

토큰당 가격만으로 선택하지 않는다. `accepted outcome`까지의 실행·실패·수정·검토 비용과 시간을 함께 집계한다. 요금제 차감량을 API 달러로 임의 환산하지 않는다. 실측 전에는 비용 절감률·속도 향상률을 제시하지 않는다. 정적 테스트·대역 CLI 성공은 실제 모델 품질을 증명하지 않는다.
